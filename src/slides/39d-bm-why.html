How the engine runs a graph

Stages need a shared record of each page

Separate programs. Each stage runs as its own process, often on its own machine, and shares no memory with the others.
No messages. Stages also never talk to each other, so one stage cannot tell another that it has finished a page.
One record per page. The engine keeps it in the DB. Every stage reads it and writes to it, and that is how the graph is coordinated.

We now go one level deeper: how does the engine actually run a graph like the one we just saw, on many machines? Here is the difficulty. Every stage is its own process, often on a different machine, and they share no memory.

They also never send messages to each other. That is deliberate, it is the same rule as before: no coordinator process that can crash and take the run with it. But it means that when Text finishes a page on machine 3, nobody tells Grounded Q&A.

So the engine keeps one small record for every page that is in flight, in the DB. Every stage reads it and writes to it. All the coordination between stages happens through this record. The next slides show what is in it. It is only two numbers.
