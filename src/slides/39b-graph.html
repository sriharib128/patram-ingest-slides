Put all those routes together and you get one graph. A page enters at the left. Each box is a model, a tool or a check. Three rules decide where a page goes and when a box may start, and we will zoom into each.

One: routing. After Understand finishes a page, a small function written by the pipeline author looks at what it found and picks the next box for that page. A chart goes to the chart reader, a table to the table reader, a formula to the LaTeX writer. A text page goes to two boxes at once, transcription and layout. It can also pick none: a blank page simply stops.

Two: needs both. Some boxes need several inputs. Grounded question answering needs both the transcribed text and the layout of the same page. Watch the label: the text arrives first, so it keeps waiting for the layout. When the layout arrives, it starts, exactly once. It does not matter which finished first or on which machine. Solid lines mean every input is needed.

Three: either one is enough. Write a question takes a table or a chart. A page is never both, so the table reader's input will never come for a chart page; waiting for both would wait forever. So it starts as soon as one input is done. Dotted lines mean one input is enough.

Three rules: route the page, needs every input, one input is enough. Every pipeline we run is built from these.
